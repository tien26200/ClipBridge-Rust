# ClipBridge Rust v0.7.4 — deleted Media slot regression & new icon

## Root-cause hypothesis supported by source
In v0.7.3, an image imported after deleting an older Media item sometimes
appeared in Media but did not reach the timeline. The Media thumbnail detector
rejected a new tile when its selection outline occupied exactly the old slot,
unless the absolute visual-difference score exceeded 20. CapCut can reuse the
same slot after a deletion, leaving that equality unchanged. This matches the
observed symptom but must still be tested on the user's exact CapCut version.

## Changes
- Accept a thumbnail as new when the selected rectangle overlaps a visibly
  changed tile, even when before/after selected coordinates are identical.
  Keep a conservative threshold for unselected slot guesses.
- Confirm the chosen tile in two consecutive screenshots with stable
  coordinates before posting Add (+) to the editor HWND.
- Keep the physical cursor stationary and preserve clipboard policy settings.
- New Windows icon: 3 coloured sectors (pink, blue and yellow) inside a
  simple transparent-backed circle, embedded in EXE resource ID 1.
- All Windows icon frame sizes generated by build.rs without Python or
  Pillow dependency at build time.

## User regression checklist
1. Exit old ClipBridge in tray; run v0.7.4 on a disposable CapCut project.
2. Copy image A, Ctrl+V in CapCut: verify A appears in Media and timeline.
3. Remove A from Media (if CapCut allows); copy a different image B,
   then Ctrl+V: verify B appears in BOTH Media and timeline.
4. Repeat with C and D and also after deleting a middle Media tile.
5. Switch Settings: Block Native ON (recommended), Clear OFF. Repeat.
6. Test optional Clear ON separately, and Block Native OFF separately.
7. Verify text Ctrl+V in other apps and CapCut internal Ctrl+C/V still work.
8. Check title-bar and system tray icons after completely restarting app.
   Windows Explorer's icon cache can retain the old graphic temporarily.
9. If B remains Media-only, send a log from:
   `%LOCALAPPDATA%\\ClipBridge\\clipbridge.log`.
   Report the IMPORT_STEP lines containing MEDIA_TILE_FOUND,
   MEDIA_TILE_STABLE, ADD_TO_TRACK_SENT and any IMPORT_FAILED line.

Tests and Windows release builds verify packaging/logic only. They do NOT
prove a timeline clip was inserted on the user's CapCut version.
The EXE is unsigned; scan with Microsoft Defender before use.
